# NexoChess canonical domain

The only public production origin for NexoChess is:

```text
https://www.nexochess.com
```

This decision applies to public navigation, Better Auth, Google OAuth callbacks,
transactional-email links, shared-game URLs, Open Graph URLs and future SEO metadata.

## Production variants

The production application must normalise these variants:

```text
http://nexochess.com/*
https://nexochess.com/*
http://www.nexochess.com/*
https://www.nexochess.com/*
```

The final destination is always:

```text
https://www.nexochess.com/*
```

The redirect preserves the pathname and query string. For example:

```text
https://nexochess.com/analysis?game=abc
->
https://www.nexochess.com/analysis?game=abc
```

NexoChess uses HTTP status `308 Permanent Redirect`. This is permanent like a `301`,
but it explicitly preserves the HTTP method and body. That prevents a canonical-host
redirect from silently converting a future POST request into a GET request.

## Cloudflare Worker exposure

A production configuration generated by
`scripts/prepare-cloudflare-production.mjs` must contain:

```json
{
    "workers_dev": false,
    "preview_urls": false
}
```

Production is intended to be served only through its configured custom domains. The
internal `nexochess-production...workers.dev` hostname and versioned preview URLs must not
be treated as public alternatives to the canonical domain.

The optional `--attach-domains` flag only writes the two approved hostnames into the local
Wrangler configuration:

```text
www.nexochess.com
nexochess.com
```

It does not run automatically. DNS and custom-domain changes require a separately reviewed
production release and explicit owner approval.

## Staging isolation

Staging remains available at:

```text
https://nexochess-staging.manuel-garcia-villaescusa.workers.dev
```

Its Wrangler configuration intentionally uses:

```json
{
    "workers_dev": true,
    "preview_urls": false
}
```

The stable staging Worker URL remains available, while version-specific public preview URLs
are disabled. Staging must never redirect to `www.nexochess.com` and must generate its own
authentication and email links from `NEXOCHESS_ORIGIN`.

## Authentication

Better Auth must resolve its origin from the selected environment configuration.
Production refuses to initialise unless:

```text
NEXOCHESS_ENV=production
NEXOCHESS_ORIGIN=https://www.nexochess.com
```

The production Google OAuth callback remains:

```text
https://www.nexochess.com/auth/account/callback/google
```

The staging callback remains:

```text
https://nexochess-staging.manuel-garcia-villaescusa.workers.dev/auth/account/callback/google
```

Do not add the apex domain, the internal production Worker or a preview URL as a second
production OAuth origin.

## Shared games and internal navigation

Archive navigation and shared-game API calls remain relative:

```text
/analysis?game=<id>
/api/public/archived-game?id=<id>
```

Relative links deliberately preserve the active environment. In production they resolve
under the canonical domain; in staging they stay in staging. Do not hardcode production URLs
inside these client flows.

## Verification

Run the static canonical-domain audit with:

```powershell
npm run verify:canonical
```

It verifies:

- the canonical origin and permanent status;
- path and query preservation;
- no redirect loop on the canonical host;
- staging isolation;
- Better Auth origin enforcement;
- production `workers.dev` and preview shutdown;
- relative shared-game navigation;
- absence of non-canonical production URLs from public client files;
- consistency with `.env.example` and operational scripts.

The step is complete in source code only after CI and CodeQL pass. It does not alter DNS,
`master` or the public website until an explicitly approved production release is deployed.
